# Внесение изменений

Создавайте отдельную ветку и небольшой pull request с причиной изменения, его эффектом и фактически выполненными проверками. Следуйте существующему TypeScript/Kotlin/PHP-стеку и оформлению; не меняйте поведение под видом переноса файлов.

Перед отправкой выполните установку по lock-файлу, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build:web` и затронутые API/Android-сценарии. Для хранения обязательны старые данные, конфликт, повтор после потерянного ответа и обновление существующего состояния. Для оптимизаций нужны одинаковые данные, окружение и несколько замеров до/после. Не обновляйте эталон только ради прохождения проверки.

Интерфейс проверяется в светлой и тёмной схемах на 360, 390, 768 и 1440 px. Сохраняйте иллюстрации, целые слова, доступные имена и цели касания. Изменения текста проверяйте на всех 14 языках, включая подстановки; автоматическая сверка ключей не заменяет смысловую вычитку.

Не разрывайте слова по буквам в интерфейсе сайта. На узких экранах переносите текст по словам и при необходимости умеренно уменьшайте шрифт, сохраняя читаемость и размеры целей касания. Для исключительно длинных непрерывных пользовательских значений предусмотрите доступ к полному тексту, например горизонтальной прокруткой, без обрезания.

Не включайте персональные данные, реальные конфигурации, токены, ключи подписи и журналы пользователей. Не публикуйте APK/AAB, внутренние рабочие планы и случайные вложения. Фикстуры должны быть синтетическими. Миграции нужны только при доказанной необходимости и проверяются на изолированной БД с планом восстановления.

Push и pull request запускают только `Source checks`. Ручной `Deploy` предназначен для согласованного выпуска сайта/API; он требует успешных проверок точного текущего SHA и сохраняет закрытые runtime-данные. Изменение инфраструктуры, схемы production-БД, доменов или публикация приложения требуют отдельной задачи. См. [порядок деплоя и отката](docs/DEPLOYMENT.md).

Лицензия на проект пока не выбрана. Условия внешних вкладов и повторного использования нужно согласовать с владельцем. Не назначайте лицензию от его имени самостоятельно.

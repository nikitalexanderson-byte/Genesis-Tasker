## Сравнение и найденные проблемы

Отдельный контрольный проход не вносил основную оптимизацию. Он самостоятельно выполнил 642 дифференциальных сравнения полной структуры и порядка результатов истории/сортировки, PHP/API-проверки исходной версии, проверки безопасного локального запуска, криптографических фикстур и сохранности продуктовых файлов. На чистом клоне коммита кода `cb4e4d3efb0a03f2bc65a987c6632b42d031f215` повторены все 642 сравнения и 17 адресных тестов загрузки/сортировки/безопасности QA: все PASS. Результаты основных изменений не принимались только по отчёту реализации.

При сравнении обнаружен прежний дефект локального загрузчика задач. В исходной функции и в настоящей исходной браузерной сборке встреча теряла `endTime`, контекст календаря и политику недопустимого дня; четыре расширенных лунных режима превращались в `lunar-days`. Исправление сохраняет дополнительные записанные поля перед прежней нормализацией известных полей и использует единый предикат допустимых повторений для облачного и локального чтения. Проверяются полные поля и даты повторений. Отдельный браузерный проход подтвердил сохранность всех пяти синтетических задач и видимое время окончания 19:45 в редакторе.

Первый полный исходный браузерный проход дал 358 PASS / 20 FAIL. Среди причин были устаревшие подписи переходов дневника и расклада и жёстко зафиксированная версия 3.1.7 вместо фактической 3.2.7. Изменены только ожидания тестов после сверки с существующим доступным UI. Сценарий совместной задачи ошибочно нажимал строку за уже открытым диалогом; исправленная последовательность сохранила все проверки прав и прошла для обоих совместных тарифов.

Пропущенный ранний click кабинета оказался отдельным прежним дефектом. Независимый контролируемый опыт задержал только NotificationDock: его появление сдвигало аккаунт на −46 px между pointerdown и pointerup, и click попадал в общий контейнер двух кнопок. Теперь место отложенных контролов резервируется сразу и учитывается при расчёте компактной шапки. Независимый повтор при той же задержке показал нулевой сдвиг и открытие кабинета с первого клика. Конечные размеры, оформление, доступные имена и функции сохранены; placeholder не интерактивен и скрыт от accessibility tree.

В предварительном широком проходе кандидата были также таймауты загрузки клиента/модулей, зависимые пропуски импорта и inbox и закрытие браузера в одном trial-сценарии. Исходные 364 PASS / 11 FAIL сохранены; они не заменены зелёной сводкой. Исправленные кабинеты/обмен повторены в отдельном Premium-проходе (84 PASS). На чистом клоне кода Lifetime, inbox, trial-сценарии и шапка дали 105 PASS / 0 FAIL; API повторён с 398 PASS. Сетевой сбой или закрытый браузер не считаются автоматически ни дефектом продукта, ни доказанно безвредным событием; здесь затронутые сценарии фактически повторены.

Промежуточный проход через полночь создавал записи вчера и затем искал их на Today нового дня. Поведение Today сохранено; проверка повторяется в пределах одной даты. Один ранний upgrade-прогон сравнил свежую запись до нормализации исходной версией с её повторной загрузкой; контроль old→old выявил прежний дефект загрузчика. Другой прогон с искусственно замороженными `Date`/`Date.now` сохранил данные, но не дождался опустошения очереди; повтор с живыми часами прошёл. Первичные результаты сохранены, конкретная причина зависимости от замороженных часов не установлена.

В подготовке экспорта исправлены отсутствие ignore-правила для `output/`, устаревшее описание logout, ссылки на исключённые внутренние материалы и проверка готовности loopback API. Последняя теперь требует идентификатор именно текущего синтетического процесса и отклоняет посторонний успешный HTTP-ответ. Отсутствующая зависимость теста хранения старых ресурсов возвращена как библиотека `ops/retain-web-assets.php`. При последующей подготовке согласованного web/API-деплоя ей возвращён CLI с разрешением только действующего корня Hostinger.

Первый GitHub CI [42532335567](https://github.com/nikitalexanderson-byte/Genesis-Tasker/actions/runs/42532335567) для `eed95a3` выявил ошибку подготовки Android job: `genesisAuroraAssets` завершилась с кодом 1. Отдельный job устанавливал JDK/SDK, но не корневые JavaScript-зависимости для встроенных web-экранов, хотя их сборщик импортирует Vite. В workflow добавлены закреплённые Node/pnpm и установка по frozen lock перед Gradle; эта предпосылка явно описана в локальной инструкции. Исходный FAIL сохраняется в истории CI, результат исправленного запуска следует проверять отдельно.

## Совместимость и визуальная проверка

Схемы БД, API-маршруты, writer-протоколы, идентификаторы, тарифные правила и форматы контейнеров не менялись. Существующие Android-исходники, переводы, миграции, шрифты и иллюстрации сохранены. Исторический распространяемый APK не включён в репозиторий исходников.

Независимая сверка Git-объектов подтвердила сохранность 4675 медиафайлов, 1115 нативных файлов, 120 миграций, 282 JSON-каталогов приложения, 15 серверных ресурсов и пяти сторонних уведомлений о лицензиях. Скрипты shell и Gradle Wrapper имеют LF и исполняемый Git-режим; submodules, symlinks и потерянных LFS pointers в экспортируемом дереве не найдено.

Веб-обновление выполнено настоящей заменой старого bundle на новый на том же тестовом origin без очистки localStorage/outbox. Сравнивались полные JSON-структуры, зашифрованные payload и исходная база операций, а не только число записей. После возобновления записи проверены опустошение очереди и единственность задачи. Сохранены 16 снимков настоящих сборок: до/после × 360/390/768/1440 px × светлая/тёмная схема. Это не утверждение о полном попиксельном совпадении: присутствуют часы, всплывающие статусы синхронизации и другое временное состояние.

Не выполнены полная смысловая вычитка всех экранов на всех 14 языках, все размеры/масштабы шрифта на Android, полный installed-data upgrade подписанного основного приложения, process death/Keystore/Room на физическом устройстве, реальный OAuth/Calendar/Tasks и внешняя доставка. Эти состояния остаются **UNVERIFIED**. Реальные личные записи для экспериментов не использовались.

## Публичный набор

Публичная история создаётся отдельно без прежней `.git`, рабочих переписок, внутренних инструкций, логов, SQLite и ключей подписи. Примеры конфигурации используют заполнители. Детерминированные криптографические векторы и синтетический архив сохранены как необходимые тестовые данные. Проверка найденных совпадений сканера не является абсолютной гарантией отсутствия неизвестных секретов.

`Source checks` выполняет read-only проверки и Android debug build на GitHub-hosted runners без secrets, SSH и распространяемых сборок. Отдельный `Deploy` добавлен после разрешения владельца на web/API-выпуск: только ручной запуск, текущий `main`, успешный последний `Source checks` того же SHA, неизменившийся incumbent SHA и единственный корень Hostinger. Порядок резервирования и rsync сохранён; Android-загрузки исключены. Push сам по себе не запускает выкладку. Предельное время source jobs — 90 минут. Лицензия проекта не назначалась.

## Последующие изменения web/API

Рабочий вход `beget/`, конфигурация и команда сборки переименованы в `web/`, `vite.web.config.ts` и `build:web`; результат — `dist-web/public_html`. Старого deployment target нет. Это перенос существующей точки входа без смены стека.

Первые Ubuntu-проверки `eed95a3` также дали 124 PASS / 2 FAIL в PHP (`habit-reminders`, `native-auth`). Причина воспроизведена отдельно: QA задавал Windows-путь `OPENSSL_CONF` системному PHP на Linux. Новый helper сохраняет явную настройку и системные defaults; bundled config выбирается только на Windows и при наличии файла. Это изменение тестового окружения, не OAuth или криптографии продукта.

После первого GitHub clone браузерный smoke дал один FAIL `business.trial-reload-keeps-server-window`: после reload не пришёл `/api/session`, на снимке остался статический shell. Независимый единичный Business-probe на том же bundle дал 4 PASS / 0 FAIL без ослабления assertions. Причина первичного сбоя не установлена; он не объявляется исправленным по одному повтору. Итоговый CI проверяет окончательную версию отдельно.

Для вытянутой иллюстрации Today горизонт установлен в 50% высоты. CDN отдавал прежнюю картинку 1536×1024 по plain URL вместо текущей 2172×724; versioned URL вернул правильные байты. `assetRevision` связан с байтами всех 81 terrain plates, а service worker при ошибке сети сначала выбирает точную кешированную версию. Сохранены идентификаторы, source/content hashes, даты, связи и обязательные сторонние уведомления. У 52 PNG удалён один необязательный metadata chunk; каждый оставшийся raw chunk, включая compressed pixels, цвет и alpha, независимо сверен побайтно с исходником. Изображения не перекодировались. Удалены неиспользуемые auth/prompt helpers; рабочие функции голосового ввода и провайдеров сохранены. Автор пакета и HTML указан как `nikitalexanderson`.

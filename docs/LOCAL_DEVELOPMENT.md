# Локальная разработка

## Без внешних сервисов

Установите Node.js 24.19.0, pnpm 11.19.0 и зависимости по lock-файлу. `pnpm build:web` создаёт статический клиент; `pnpm qa:serve` запускает его с изолированным PHP API. Вход выполняется по напечатанной ссылке синтетического тарифа. Записи локальные; сервер привязан к loopback.

Для HMR используйте `pnpm dev`. Альтернативный vinext/Cloudflare runtime использует локальные bindings и не заменяет PHP API. `build:web` только создаёт локальные файлы.

| Переменная | Назначение / безопасный пример |
| --- | --- |
| `GENESIS_API_URL` | API статической сборки; по умолчанию `/api` |
| `GENESIS_BASE_PATH` | Путь статической сборки; по умолчанию `/` |
| `GENESIS_MINDMAPS` | `true` включает существующий web-модуль карт; серверные права проверяются отдельно |
| `NEXT_PUBLIC_GENESIS_API_URL` | API альтернативного vinext-клиента |
| `GENESIS_QA_PHP` | Абсолютный путь к совместимому локальному PHP CLI |
| `GENESIS_POLLING` | `true` для файловых систем, которым нужен polling HMR |
| `GENESIS_LOCAL_D1_BINDING`, `GENESIS_LOCAL_R2_BINDING` | Необязательные имена локальных Cloudflare bindings; по умолчанию отсутствуют |

Встраиваемые в клиент значения публичны по определению: секреты в них недопустимы. `.env.example` содержит только безопасные значения. `GENESIS_FULL_QA*` назначаются тестовыми runner-ами и не должны применяться к действующему сервису.

## Настоящие тестовые интеграции

Используйте отдельный тестовый домен, аккаунты и календарь. Скопируйте `server/config.example.php` в игнорируемый `server/config.php` только в изолированном экземпляре. Настройте собственные `app_url`, `db_path`, `session_path`, ключ и OAuth credentials; ни один путь не должен указывать на production. Пример конфигурации описывает возможности и значения по умолчанию, а не готовое подключение к действующему сервису.

PHP обслуживает `server/public/`; `server/src/`, конфигурация и runtime остаются вне web-root. При первом обращении применяются миграции SQLite. Для OAuth смотрите [GOOGLE-OAUTH-PUBLISHING.md](GOOGLE-OAUTH-PUBLISHING.md). Google-вход сам по себе не даёт доступ к Calendar/Tasks.

После создания собственной тестовой конфигурации `php server/tools/initialize-config.php server/config.php` заменяет `REPLACE_WITH_RANDOM_KEY` случайным ключом и ограничивает права файла. Запускайте команду только для своей локальной копии. Закрытый ключ вместе с БД нужен для восстановления данных и не публикуется.

Платежные интеграции требуют sandbox провайдера и отдельных credentials. Локальные контрактные тесты не проводят платежи и не отправляют уведомления. Production-конфигурация, БД, signing keys и пользовательские записи в исходники не включаются.

## Android

Нужны JDK 25, SDK `platforms;android-37.2`, `build-tools;37.0.0`, platform-tools и переменные `JAVA_HOME`/`ANDROID_HOME`. `android/local.properties` — локальный игнорируемый файл. Gradle Wrapper закреплён в исходниках. Для локальной проверки собирайте debug с `-PgenesisUrl=https://localhost.invalid/`.

Перед Gradle выполните корневую установку `pnpm install --frozen-lockfile` с Node.js 24.19.0 и pnpm 11.19.0. Задача `genesisAuroraAssets` собирает встроенные экраны Авроры и резервных копий через Vite; ей нужны JavaScript-зависимости из корня проекта даже при сборке только Android. В CI каждый job устанавливает их отдельно.

На проверявшемся Windows-окружении первый запуск Java не смог скачать Gradle через доступный официальный URL (`Connection refused`). Новая загрузка прошла с `JAVA_OPTS=-Djava.net.preferIPv4Stack=true`; для Gradle JVM использовался тот же флаг в `org.gradle.jvmargs`. Это сетевой параметр конкретной среды, а не требование сменить версию или отключить TLS. В чистой проверке использовались новый `GRADLE_USER_HOME` и заново загруженные зависимости.

HTTP-интеграционные JUnit-тесты и инструментальные тесты требуют отдельного loopback backend/эмулятора. Обычный `testDebugUnitTest` часть таких тестов пропускает; это видно в JUnit XML. Для устройства явно выбирайте ADB serial. Основное приложение не удаляется и его данные не очищаются.

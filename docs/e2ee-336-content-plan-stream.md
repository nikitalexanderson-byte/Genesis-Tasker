The current batch planner collects reconciled contents, every encrypted file
chunk and local-content writes before one publication. Source staging and the
bounded v1 file writer/reader do not by themselves remove those allocations.

The next writer must consume one semantic record or file stream at a time and
persist each sealed chunk in encrypted local quarantine. It must preserve the
existing v1 file format,64MiB per-file bound,64KiB shared-comment bound and
remote/local placement. It must not enlarge a heap or pass a whole account
through the compatibility readers. Per-path compatibility needs explicit input
and history bounds; the archives/common-reader path requires actual streams.

Each plan attempt needs its own opaque ID, encrypted journal and immutable
complete manifest. A failed attempt keeps its journal/parts and the original
source; retries cannot reuse a partially written attempt's record IDs. A prefix
has no transport or restore authority. Publication of a complete plan is a local
transaction after readback, not permission to start network writes. The
coordinator must bind that exact plan to its committed source reference, lease,
target generation, device/context and existing CAS before uploads can begin.

Keep only bounded descriptors, duplicate identities, coverage and receipts in
memory. Persist remote envelopes individually; local-only normalized content
must remain under local-snapshot and never enter an upload descriptor. Readback
must authenticate all ordered file chunks and actual EOF with the bounded file
reader, compare complete logical bytes, verify local contents and recheck the
original-source/actor fence before publication. Every required registry path and
all known source histories must complete. Missing, partial or unknown histories
must still refuse, including incomplete source journals.

## Implemented component boundary and pending acceptance

Web `ProtectedMigrationContentPlan` and native `E2eeContentPlan.Writer` reserve
an attempt-specific encrypted journal, persist each remote envelope/local part
with its journal update and authenticate record readback before acknowledging
that record. A final complete manifest and marker share the local CAS transaction.
Remote file envelopes retain the existing v1 format; shared comments retain
their single-envelope format. Device-only content cannot enter the upload plan.
Complete-plan readers validate all metadata, exact attempt inventory and every
record's bounded readback using SHA-256 of its complete original bytes. Native
uses JCA, web uses the pinned incremental implementation. Metadata syntax has a
separate4MiB/250000-node bound; the old file manifest keeps256KiB/10000 nodes.
The existing local-content128MiB aggregate admission also remains explicit.

The reader accepts a read-only vault interface; no old private signing key is
a read parameter. Production authenticated handoff/custody and source/lease/CAS
binding still belong to the unfinished coordinator integration. The caller's
`assertSourceComplete` is an integration precondition, not a server boolean or
proof that the current component has reconciled every actual product source.
The v3 coordinator continues to refuse before transport. Partial plan discovery/
recovery and capacity across every retained attempt still need that integration.

# Проверка изменений

`pnpm test` запускает аудит ключей и подстановок 14 языков, сверку нативных каталогов, vinext build и все корневые `tests/*.test.mjs`. `pnpm test:unit` предполагает уже выполненную сборку: проверки рендеринга читают её результат. Новые файлы автоматически включаются в набор.

`backend-run.mjs` создаёт отдельные SQLite, конфигурацию и сессии для каждого PHP-набора; отключает `curl_exec` и `mail`, проверяет завершение sentinel-ом и очищает только принадлежащий прогону runtime. `backend-api.mjs` использует настоящее локальное HTTP API, пять тарифов и конкурентные записи. Проверяются запреты, ревизии и повторы, а не только видимость кнопок.

`web-run.mjs` обслуживает именно `dist-web/public_html`, запускает изолированный PHP API и запрещает браузеру внешние HTTP(S)-запросы. Проверяются создание/редактирование, второй клиент, офлайн, удаление, календарь, привычки, дневник, карты, расклады и тарифы. Снимки на 360, 390, 768 и 1440 px в обеих схемах сохраняются в каталоге прогона. Старый вспомогательный визуальный эксперимент внутри набора не заменяет сравнение двух настоящих сборок.

`pnpm qa:full` сохраняет статусы стадий и по умолчанию включает Android JVM tests и debug build. `--scope=web` ограничивает проход web/API и фиксирует Android как UNVERIFIED. JUnit cases с `assumeTrue` не считаются выполненной HTTP-интеграцией. Эмулятор, физическое устройство, Google, платежи и доставка уведомлений проверяются отдельно.

Сценарии кабинета и обмена данными в `web-317.mjs` предполагают завершённую загрузку документа: ждут `networkidle` и смонтированную шапку. Проверка размеров/схем не перезагружает уже подготовленную страницу перед кликом. Это не проверка раннего нажатия во время начальной перестройки шапки; известный результат такого отдельного прохода указан в [VERIFICATION.md](VERIFICATION.md). Повторные клики и автоматические retries не используются.

Для адресной проверки сохранённого совместного доступа после истечения тарифа: `node scripts/qa/web-run.mjs --suite=retention --run-id=local-retention`. Набор сохраняет проверку перехода из Today, закрытия карточки, навигации по проектам, повторного открытия, запретов платных записей и отказа экспорта.

`node scripts/qa/web-run.mjs --suite=header --run-id=local-header` проверяет реальное нажатие во время загрузки шапки: задерживает только два JS-модуля, нажимает кнопку кабинета, отпускает её после появления отложенных контролов и требует открытия кабинета без второго клика. Проверяются координаты, размеры и цель отпускания на 360/390/768/1440 px в обеих схемах. Этот же набор включён в полный браузерный проход.

## Данные и обновления

Создайте синтетические данные в предыдущей версии. На том же origin запустите новую сборку, не очищая localStorage/IndexedDB/cache/outbox; сравните записи, связи, настройки и ожидающие изменения. Проверьте истёкшую сессию, два клиента, потерю ответа, конфликт и отказ хранилища. Для криптографии отдельно проверяются чтение старого контейнера, запись нового и отказ при подмене.

`history-projection-baseline.json` получена до оптимизации и содержит только синтетические данные. Проверки сравнивают данные и порядок целиком, замораживают вход и контролируют независимость повторных вызовов. Существующие сценарии истории/наград/backup дополнительно проверяют бизнес-инварианты. Изменение эталона требует объяснения и независимой проверки.

## Достоверность

PASS означает выполненную проверку, FAIL — подтверждённое несоответствие, UNVERIFIED — невыполненную проверку с причиной. Сбой старого сценария сначала сопоставляется с исходным приложением. Селектор обновляется только после подтверждения актуального доступного UI. Ожидаемое поведение не ослабляется ради зелёного результата.

Публикуемый коммит проверяется новой установкой по lock-файлу, сборкой и критическими сценариями из чистого клона/экспорта. Методика замеров — в [PERFORMANCE.md](PERFORMANCE.md); результаты конкретного состояния — в [VERIFICATION.md](VERIFICATION.md).
